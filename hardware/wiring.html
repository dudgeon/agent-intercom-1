Agent Intercom — Prototype Wiring & Setup

v0 · single unit · Raspberry Pi 5 + 7.5″ mono e-ink + far-field mic + I²S speaker

Derived from hardware/BOM.md and hardware/requirements.md (ADR 0003 / 0007). Pin numbers are physical (board) pins; signal names use BCM GPIO numbering. Do all wiring with the unit powered off and unplugged.

Two traps this layout designs around.
  1. Pi 5 has no analog audio jack → sound comes from an I²S amp (MAX98357A) + speaker.
  2. The Waveshare e-ink driver defaults PWR = GPIO18, which is also the I²S bit-clock. We tie the panel's PWR pin to 3V3 (or remap it) so GPIO18 is free for audio. If you skip this, audio or the panel will mis-behave.

1 · System overview

The Pi 5 is the host. The display hangs off SPI0, the speaker off I²S, the mic array off USB, and the human controls (mic switch, status LED, optional encoder + buttons) off plain GPIO.

2 · GPIO pin map — the single source of truth

The 40-pin header as you look down on the board, USB ports toward you. Pin 1 is top-left. Colored pins are used; gray are spare. Wire to exactly these and the software defaults below "just work."

e-ink (SPI) I²S audio mic switch status LED encoder (opt) buttons (opt) 3V3 5V GND spare
HAT vs. stacking. The e-ink ships as a HAT that sits on all 40 pins. To also reach the audio/switch/LED pins, use a 2×20 stacking header (or wire the panel through its driver board with jumpers). Whichever you choose, the signal pins above don't change.

4 · Setup, step by step

Each step ends with a ✔ test that must pass before moving on. Run from another machine over SSH.

Flash the OS & first boot

Use Raspberry Pi Imager → Raspberry Pi OS (64-bit), Bookworm. In the gear/⚙ options set hostname intercom-kitchen, enable SSH, and set Wi-Fi + user.

Pick Bookworm, not Trixie — there's a known regression where the MAX98357A I²S card is detected but produces no sound on Trixie. Bookworm is the safe target for v0.
✔ test — 
ssh pi@intercom-kitchen.local
cat /etc/os-release   # expect: VERSION_CODENAME=bookworm
uname -m              # expect: aarch64

Update & enable SPI + I²S

sudo apt update && sudo apt full-upgrade -y
sudo raspi-config nonint do_spi 0          # enable SPI
# enable the I²S amp by adding overlays:
echo 'dtparam=spi=on'        | sudo tee -a /boot/firmware/config.txt
echo 'dtoverlay=max98357a'   | sudo tee -a /boot/firmware/config.txt
sudo reboot
✔ test — 
ls /dev/spidev0.*     # expect: /dev/spidev0.0  /dev/spidev0.1
aplay -l              # expect a card listing MAX98357A / I2S

Wire & test the e-ink panel

Power off & unplug. Seat the HAT (or wire per the table, tying PWR→3V3). Power back on.

sudo apt install -y git python3-pip python3-pil python3-numpy python3-spidev python3-gpiozero python3-lgpio
git clone https://github.com/waveshareteam/e-Paper.git
cd e-Paper/RaspberryPi_JetsonNano/python/examples
python3 epd_7in5_V2_test.py     # use the variant matching your panel rev
✔ test — the panel runs the demo: full-screen flashes, then test text/patterns/images. A blank panel almost always = PWR/CS/contrast (see Troubleshooting).

Wire & test the speaker

Wire the amp (5 lines) and the speaker to the amp's +/− terminals.

# make the I2S card the default, then:
speaker-test -D default -c2 -twav -l1
# or:
aplay /usr/share/sounds/alsa/Front_Center.wav   # you should hear "Front, Center"
✔ test — you hear clear audio. No sound on Trixie? You're on the wrong OS (Step 1 warning).

Test the far-field mic (USB)

Plug the ReSpeaker array into a USB-A port.

arecord -l            # note the card name, e.g. card 2: ArrayUAC10
arecord -D plughw:CARD=ArrayUAC10,DEV=0 -d5 -f S16_LE -r16000 /tmp/t.wav
aplay /tmp/t.wav      # play back what you said, across the room
✔ test — your across-room voice is clearly captured in the playback.

Wire & test the mic switch + status LED

Switch: GPIO23↔GND. LED: R/G/B via resistors to GPIO5/6/13, cathode to GND.

python3 - <<'PY'
from gpiozero import Button, RGBLED
from signal import pause
sw  = Button(23, pull_up=True)            # pressed/closed = "muted"
led = RGBLED(red=5, green=6, blue=13)     # PWM via lgpio on Pi 5
def muted():  led.color=(1,0,0); print("MIC MUTED")
def live():   led.color=(0,1,0); print("MIC LIVE")
sw.when_pressed = muted; sw.when_released = live
live() if not sw.is_pressed else muted()
pause()
PY
✔ test — toggling the switch flips both the console line and the LED color.
Why a plain RGB LED, not a WS2812? Addressable-LED libraries (rpi_ws281x) rely on PWM/DMA timing that the Pi 5's new RP1 I/O controller doesn't support cleanly yet. A 3-GPIO RGB LED via gpiozero/lgpio is rock-solid on Pi 5. (The mic array's own LED ring is a fine secondary indicator if you want one.)

(Optional) Wire & test encoder + buttons

python3 - <<'PY'
from gpiozero import RotaryEncoder, Button
from signal import pause
enc = RotaryEncoder(27, 22, max_steps=0); push = Button(26, pull_up=True)
btns = {16:"B1",20:"B2",12:"B3",4:"B4"}
enc.when_rotated = lambda: print("wheel", enc.steps)
push.when_pressed = lambda: print("wheel click")
for p,n in btns.items(): Button(p, pull_up=True).when_pressed = (lambda n=n: print("press", n))
pause()
PY
✔ test — every control emits exactly one clean event per actuation (no bounce storms).

Integration smoke test

One script that proves the pieces cooperate: switch live → LED green + record 3s → play back; switch muted → LED red, no capture. This is the hardware contract the device host (apps/) will later drive from the gateway.

python3 - <<'PY'
import subprocess
from gpiozero import Button, RGBLED
sw=Button(23,pull_up=True); led=RGBLED(5,6,13)
if sw.is_pressed:
    led.color=(1,0,0); print("muted — refusing to record")
else:
    led.color=(0,1,0); print("live — recording 3s…")
    subprocess.run("arecord -d3 -f S16_LE -r16000 /tmp/s.wav",shell=True)
    subprocess.run("aplay /tmp/s.wav",shell=True)
PY
Hardware verified. Next: the apps/ host (pending the Q4 ADR) wires these same pins to the gateway WebSocket — switch/LED → mic state, buttons/wheel → MCP App events, e-ink ← rendered frames.

5 · Troubleshooting

SymptomLikely cause / fix
No /dev/spidev*SPI not enabled — re-run Step 2, confirm dtparam=spi=on, reboot.
aplay -l shows no MAX98357AOverlay missing or on Trixie. Confirm dtoverlay=max98357a in /boot/firmware/config.txt; reboot; if still absent, reflash Bookworm.
e-ink stays blankPWR not tied high (GPIO18 stolen by audio), CS/DC swapped, or wrong demo for the panel rev. Re-check the e-ink table; verify PWR→3V3.
Audio and panel fightClassic GPIO18 collision — you skipped tying e-ink PWR to 3V3. Fix the PWR jumper.
LED does nothing / errorsDon't use WS2812 on Pi 5; use the 3-GPIO RGB LED shown. Ensure resistors + cathode to GND.
gpiozero "pin factory" errorInstall python3-lgpio; on Pi 5 lgpio is the working backend.
Buttons trigger many timesSwitch bounce — add bounce_time=0.05 to the gpiozero Button.
